# 설치 경로 선택

한줄은 설치한 서버에서 실행되는 개인용 웹앱입니다. 서버에 접속하는 브라우저가 화면을 제공하고, 메모·첨부·인증 설정은 그 서버의 SQLite에 저장됩니다. 별도 외부 DB를 연결할 필요가 없습니다.

| 원하는 사용 방식 | 선택할 안내 |
| --- | --- |
| 내 컴퓨터에서 먼저 사용 | [로컬](LOCAL.md) |
| NAS에 두고 컴퓨터·휴대폰에서 접속 | [NAS](../deploy/synology/README.md) |
| AWS 계정의 EC2에서 실행 | [AWS](AWS.md) |
| 홈 서버·Linux VM에서 실행 | [일반 서버](SERVER.md) |

## 공통 준비

Docker Compose v2의 `docker compose` 명령을 사용합니다. 서버 CPU는 사용하는 Python·Caddy 이미지가 지원해야 하며 일반적인 amd64·arm64 환경을 대상으로 합니다. Docker 미지원 NAS는 이 안내의 대상이 아닙니다. 소스 빌드는 서버의 아키텍처를 사용합니다. 실제 NAS 모델이나 AWS 계정 전체에 대해 검증한 것은 아닙니다.

HTTPS 원격 접속에는 고정 도메인, 그 서버로 연결되는 DNS, 유효한 인증서와 네트워크 경로가 필요합니다. 로컬 PC 전용은 `http://localhost:8787`을 사용합니다. 휴대폰에서 `localhost`를 열면 휴대폰 자신을 가리킵니다.

```text
컴퓨터·휴대폰 브라우저
        ↓ 같은 HTTPS 주소
NAS 프록시 또는 Caddy
        ↓
한줄 컨테이너
        ↓
서버 로컬 디스크의 SQLite 영속 볼륨
```

메모는 하나의 서버에서 보관합니다. 독립적으로 설치한 두 서버 사이에는 자동 동기화가 없습니다. 다른 서버로 이동하려면 [백업·복구·이전](BACKUP.md)을 참고하세요.

## 설정 파일

| 파일 | 용도 |
| --- | --- |
| `compose.yaml` | 로컬 기본 실행, 앱·백업 영속 볼륨 |
| `compose.nas.yaml` | NAS·기존 HTTPS 프록시에 연결하는 덮어쓰기 설정 |
| `compose.https.yaml` | Caddy HTTPS 프록시를 함께 실행하는 덮어쓰기 설정 |
| `deploy/server/env.example` | Caddy용 도메인 예시 |
| `deploy/synology/env.example` | NAS용 HTTPS origin 예시 |
| `deploy/compose.restore.yaml` | 백업을 새 데이터 볼륨으로 복원할 때 사용 |

Docker Compose는 저장소 루트의 `.env`를 설정 치환에 사용합니다. Python으로 앱을 직접 실행할 때는 `.env`를 자동으로 읽지 않으므로 환경변수를 별도로 전달합니다. NAS 설정과 Caddy 설정은 설치 환경에 맞춰 하나를 선택하세요.

앱을 도메인의 루트 경로(`/`)에서 제공하세요. `/memo` 같은 하위 경로 설치는 지원하지 않습니다. `MEMO_PUBLIC_ORIGIN`은 브라우저 주소와 정확히 일치해야 합니다.

## 설치 후 확인

1. 최초 비밀번호로 로그인한 뒤 개인 비밀번호로 변경합니다.
2. 테스트 메모와 첨부를 작성하고 새로고침해 보존을 확인합니다.
3. 컨테이너를 재시작하고 메모가 그대로인지 확인합니다.
4. 다른 기기에서 같은 HTTPS 주소로 로그인해 메모를 확인합니다.
5. [백업 명령](BACKUP.md)을 실행해 복원 검증까지 확인합니다.

개별 서버·클라우드 계정이나 실제 데이터에 자동으로 연결하지 않습니다. 이 저장소의 구성은 사용자가 선택한 서버에 직접 설치하기 위한 것입니다.
